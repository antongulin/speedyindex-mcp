# Src contract

## Purpose

Serve SpeedyIndex account/task reads, read-only retry planning, and guarded indexing, index-check and backlink-check previews/submissions over MCP stdio.

## Ownership

`cli.ts` owns arguments, exclusive local fingerprint/init/migration modes, trusted configuration and transport; `server.ts` registers tools. `client.ts`, `task-status.ts` and `task-report.ts` own read HTTP, schemas and normalization. `read-budget.ts` owns trusted internal invocation meters, single-read leases and awaitable settlement/close. `retry-observation.ts` owns internal same-key two-pass collection and semantic work/retention meters; `plan-retry.ts` owns source/corpus/coverage/regular quote and pure comparison identity; `plan-retry-result.ts` owns strict public variants, semantic validation and the bounded application envelope. `submission-contract.ts` owns pure submission scalar/unit/authorization contracts and coordinator DTOs; `create-indexing-task.ts` retains their public indexing aliases and owns indexing schemas, frozen bodies, quotes and ACK classification. `create-index-check.ts` owns pure index-check input, reservation quotes, result validation and ACK classification; `create-backlink-check.ts` owns the corresponding backlink contracts with target counts. `submission-policy.ts` owns private policy loading and trusted context; `submission-host.ts` owns the shared coordinator, internal indexing, index-check and backlink-check strategies and guarded paid dispatch. `submission-ledger.ts` owns versioned V1/V2 SQLite validation, intent/reservation transactions, atomic internal retry admission and explicit guarded offline maintenance; `retry-ledger-snapshot.ts` owns the bounded internal projection, deeply frozen DTOs and exact revision/manifest hashes. The eight files under `tools/` own their public adapters. The planner adapter forwards only input and the actual SDK signal to `SubmissionHost.planRetryToolResult`; it returns the owned envelope unchanged.

## Local Contracts

Validate one family and exactly one ID form, preserve opaque IDs, correlate returned roots by exact ID, and treat `unreturnedIds` as omissions from one response, not proof that tasks do not exist. `get_task_report` sends one JSON POST to one of six fixed report routes. Report IDs remain opaque and are correlated exactly. Generic reports return validated URL strings unchanged; backlink reports return one page with explicit page/limit defaults and opaque finite-JSON donor objects. Do not infer completeness or fresh indexing truth. Cap read decoded response-body bytes at 16 MiB before JSON decoding. The read client has no paid method. Reject redirects, do not retry, pass SDK cancellation to fetch and retain the HTTP deadline. Keep CodeGraph outside runtime dependencies.

The three task-read methods optionally accept a trusted internal invocation budget; public adapters and `getBalance` keep their existing path. One captured monotonic origin bounds 64 entered fetches (including failures/repeats), 32 MiB aggregate decoded chunks and 60 seconds. Keep the per-response 16 MiB ceiling and clamp each request to the finite positive client timeout, 10 seconds and remaining horizon. Trusted lower-only construction captures runtime functions/receivers once; no external selector. Charge every fulfilled chunk before copying or checking cancellation, even when discarded. Exact exhaustion may complete; deny the next admission. Latch the first classified failure before cleanup, preserving domain transport causes through the three outer catches. Await owned fetch/read/cancel/captured-reader.closed receipts before releasing the reader, timer/listeners and lease. Close permanently denies reuse and awaits that same receipt; ordinary failed reads do not reject a clean close. Unexpected cleanup failure poisons admission/close with fixed internal `CleanupFailed` while preserving an existing read cause. The internal collector checkpoints this same caller-owned budget around its awaits and synchronous work. The production host establishes this origin before initial SQL and holds its actual shared guard through final SQL/UTC/proof checks and awaited settlement/close; the budget itself supplies no separate composition or paid guard.

Validate application error results locally because SDK output validation skips `isError`. Do not expose keys, credential fingerprints, paths, provider bodies/errors or raw capabilities/tokens.
