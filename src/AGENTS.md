# Src contract

## Purpose

Serve SpeedyIndex account/task reads and guarded indexing, index-check and backlink-check previews/submissions over MCP stdio.

## Ownership

`cli.ts` owns arguments, exclusive local fingerprint/init/migration modes, trusted configuration and transport; `server.ts` registers tools. `client.ts`, `task-status.ts` and `task-report.ts` own read HTTP, schemas and normalization. `read-budget.ts` owns trusted internal invocation meters, single-read leases and awaitable settlement/close. `retry-observation.ts` owns internal same-key two-pass collection and semantic work/retention meters; `plan-retry.ts` owns source/corpus/coverage/regular quote and pure comparison identity. `submission-contract.ts` owns pure submission scalar/unit/authorization contracts and coordinator DTOs; `create-indexing-task.ts` retains their public indexing aliases and owns indexing schemas, frozen bodies, quotes and ACK classification. `create-index-check.ts` owns pure index-check input, reservation quotes, result validation and ACK classification; `create-backlink-check.ts` owns the corresponding backlink contracts with target counts. `submission-policy.ts` owns private policy loading and trusted context; `submission-host.ts` owns the shared coordinator, internal indexing, index-check and backlink-check strategies and guarded paid dispatch. `submission-ledger.ts` owns versioned V1/V2 SQLite validation, intent/reservation transactions, atomic internal retry admission and explicit guarded offline maintenance; `retry-ledger-snapshot.ts` owns the bounded internal projection, deeply frozen DTOs and exact revision/manifest hashes. The seven files under `tools/` own their public adapters.

## Local Contracts

Use fixed production HTTPS endpoints and the raw Authorization key. `get_balance` reads the account endpoint; `list_tasks` reads one validated task-list page; `get_task_status` sends one JSON POST to one of six fixed read-only status routes. Validate one family and exactly one ID form, preserve opaque IDs, correlate returned roots by exact ID, and treat `unreturnedIds` as omissions from one response, not proof that tasks do not exist. `get_task_report` sends one JSON POST to one of six fixed report routes. Report IDs remain opaque and are correlated exactly. Generic reports return validated URL strings unchanged; backlink reports return one page with explicit page/limit defaults and opaque finite-JSON donor objects. Do not infer completeness or fresh indexing truth. Cap read decoded response-body bytes at 16 MiB before JSON decoding. The read client has no paid method. Reject redirects, do not retry, pass SDK cancellation to fetch and retain the HTTP deadline. Keep CodeGraph outside runtime dependencies.

The three task-read methods optionally accept a trusted internal invocation budget; public adapters and `getBalance` keep their existing path. One captured monotonic origin bounds 64 entered fetches (including failures/repeats), 32 MiB aggregate decoded chunks and 60 seconds. Keep the per-response 16 MiB ceiling and clamp each request to the finite positive client timeout, 10 seconds and remaining horizon. Trusted lower-only construction captures runtime functions/receivers once; no external selector. Charge every fulfilled chunk before copying or checking cancellation, even when discarded. Exact exhaustion may complete; deny the next admission. Latch the first classified failure before cleanup, preserving domain transport causes through the three outer catches. Await owned fetch/read/cancel/captured-reader.closed receipts before releasing the reader, timer/listeners and lease. Close permanently denies reuse and awaits that same receipt; ordinary failed reads do not reject a clean close. Unexpected cleanup failure poisons admission/close with fixed internal `CleanupFailed` while preserving an existing read cause. The internal collector checkpoints this same caller-owned budget around its awaits and synchronous work. The production owner must still establish one origin before initial SQL, final SQL/UTC/proof checks and composition exclusion through awaited close; the budget itself supplies no composition or paid guard.

The submission host accepts only its loaded immutable trusted policy/key/state reference, with no MCP authority override. Preview performs pure validation/quoting without state or network. Submit opens existing complete V1 or V2, handles exact replay without dispatch, prepares/claims once, yields to actual I/O after prepare and claim, and checks cancellation before its single fixed-route POST. No SQL transaction spans an await. Enforce the separate 2 MiB request/64 KiB response bounds and strict root ACK identity. Record the outcome even after caller cancellation; distinguish unrecorded HTTP observations from durable state. Validate application error results locally because SDK output validation skips `isError`. Do not expose keys, credential fingerprints, paths, provider bodies/errors or raw capabilities/tokens.

All three create adapters use the same passed host and forward `context.mcpReq.signal`. Backlink admission requires enabled configuration, explicit `allowBacklinkChecks: true` and a complete private three-unit profile from the admitted snapshot; the key-free inactive view cannot override it. Tokens have a local 2026-10-21 floor of 2 per donor from the [official English API](https://en.speedyindex.com/api.php#backlink-create); other fees and target-count pricing effects remain unknown. Explicit zero in another unit is an operator reservation choice. Invalid new flag/profile fields block all three create tools until corrected and all hosts restart; both absent preserve legacy canonical identity, while present false/profile values bind policy identity.

Backlink target strings are 1 to 50 nonblank safe Unicode values up to 8,192 UTF-8 bytes each. Preserve case, spaces, order and exact duplicates without DNS parsing. Keep the 10,000 unique donor URL and 2 MiB whole-body limits. Serialize optional title, urls, then target_domains; bind the full body and both counts in the own quote. Preserve targetDomainCount through the structural coordinator DTO without widening older schemas. V1 holds only exact ordered donor URLs across target lists/families and stores no raw target list or pairs. Exact admitted replay precedes busy/current ACK and creates no new POST. Backlink ACKs need the exact family and conservative checker echoes; accepted denotes acknowledged creation, not completed analysis.

The optional private `retry` policy object is strict and contains exactly `enabled`, `allowUnattributedParents`, and positive safe-integer `maxAttemptsPerSource`. Its copied, frozen values join canonical policy identity only when present; absence preserves the prior digest. Malformed retry data invalidates the complete policy and blocks all three create tools until corrected and every cooperating host restarts. This field alone provides no external-parent verification, retry admission, or public retry tool.

`submission-ledger.ts` stores request digests, exact private URL strings, unit reservations and state transitions, without keys, titles or raw bodies. Explicit CLI init calls `initializeLedger` or `initializeLedgerV2` on a new private leaf; explicit offline `migrateLedgerV2` requires a new verified private backup before additive DDL. Validate the entire CLI grammar before reading keys/configuration or starting filesystem, network or server work. Local modes are exclusive and expose no MCP selector. The host calls `openLedger` only on submit; normal open verifies complete V1/V2 before configuring WAL and never bootstraps, repairs or resets records. SQLite opening and reads can touch SHM bookkeeping even before version rejection. Unresolved holds persist. Synchronous SQL can delay stdio/cancellation; the HTTP deadline does not bound the whole tool. The ledger coordinates cooperating processes sharing one canonical local store/key/scope; it supplies no provider wallet cap, exactly-once guarantee, account identity or power-loss guarantee. Preserve exact V1 core identities/rows/events/ownership and grouped event validation. V2 ordinary context creation is atomic; legacy replay never acquires invented lineage. `readRetrySnapshot` uses one guarded no-create query-only read transaction and closes before returning a copied deeply frozen DTO; physical WAL/SHM bookkeeping or checkpoint main-file writes remain possible. Its complete selected-key projection spans all budget scopes/families with explicit legacy/ambiguity gaps; it supplies no provider-wide coverage or eligibility. Technical ceilings are 2,000 intents, 6,000 events, 20,000 URL rows and 16 MiB projection/DTO bytes; excess yields unavailable, never truncation. `readRetryPlanningState` shares that guarded query-only boundary: complete snapshot plus nonmutating current UTC/stored-period compatibility, exact BigInt scope usage/three-unit caps and all-state lifetime counts for the exact binding/parent across scopes/policies/periods. Check wall/period after SQL and before return. `readRetryReplay` audits existing V2 schema/history and compares the original full V1 replay predicate plus retry context without a full snapshot projection or current revision/cap/hold/proof requirement; original policy values are comparison only. It returns missing/conflict/durable state, no ownership capability. Both readers close before immutable results or fixed unavailable; neither admits verified external work. The separate trusted local-only `openRetryLedgerV2` factory prepares retry context/core/holds atomically against the current revision and exact unambiguous accepted local same-engine indexer manifest/subset, excluding known own retry children as parents. Full existing retry replay precedes current revision/resource/overlap/cap gates and grants no capability; ordinary/retry IDs cannot change modes. Dispatching/unknown retry children without durable IDs block new admission. V2 accepted-outcome recording checks ownership before duplicate-reference/self-parent guards; failure retains dispatching holds. These APIs supply no public retry tool, external adoption, approval or paid authority. Keep transaction ownership in core, no async SQL or runtime authority selectors. Follow [maintenance](../docs/state-maintenance.md) for offline/uncertain-commit and no-restore boundaries.

The internal `composeVerifiedRetryAdmission` owns a separate configuration-bound opaque-proof registry and writer façade, sharing the original core transaction and owner/ACK guards. Capture methods/receivers/clocks/configuration once. Collection and any own writer are mutually exclusive in both directions; no reader/transaction survives the verifier await. Only collection and missing-ID new preparation enforce current retry/adoption/count permission. Exact original context/full V1 identity replay precedes proof lookup, consumption, current policy and clock gates, even when a currently valid bound policy disables retry. Consume new-work proof after the actual lock, compare all private input/binding/configuration and ledger identity, reproject complete local state and recheck fresh monotonic/UTC clocks immediately before insertion. Validate/copy/freeze matching first-unique report partitions, safe exact URLs and bounded metadata; never truncate or seal caller facts. Pure `computeRetryPlanFingerprint` enumerates public-safe fields without request/time/raw binding/path/ownership, while retaining opaque revision/policy/authorization/body/quote identities. The internal collector and pure proposal core do not issue these proofs. The configured production verifier/reader/guard/proof composition and public semantic replay adapter are required later; fixtures are controlled constructor wiring only. External observed manifests use their own digest domain and never create local parent history. Document unreconstructible historical observation/provenance limits and remaining collector meters and production use of the HTTP budget.

The internal collector validates the strict default-Google selector again before HTTP, captures the configured key and actual methods, and reads Google regular, Google drip without a PPR subfilter, and Yandex regular streams inclusively twice. It inspects every required status, direct provider relation, selected report and relevant final direct retry-child report; changes or omissions stop collection without retry, fallback, truncation or a third pass. Distinct exact family/ID root and child references have separate 2,000/4,000 ceilings across both passes; status visits repeat against 12,000. Status bodies obey both 1,000 IDs and 65,536 UTF-8 bytes, including the 4,096-byte safe-ID bound. Reserve mandatory fence reads and visits before report work. The optional fourth report argument captures its raw-entry method/receiver before await, only for budgeted Google/Yandex indexer reports. Charge actual parsed indexed/unindexed array lengths before normalization, including invalid values, duplicates and fence visits: 10,000 per report and 40,000 per invocation. Omitted hooks preserve public reads.

The pure core requires coherent finality within a representable RFC3339 profile with validated calendar dates and offsets and seconds `00`–`59`, greatest creation chronology and no older fallback past uncertainty or ties. Valid RFC3339 leap-second timestamps block as `ConflictingEvidence` without older-source fallback. Local corpus readiness requires exact unique union equality with the durable manifest, including refusal of extra URLs. External count-complete observed corpora need explicit private permission and retain unknown original ancestry, with the existing provider-report manifest domain. All-family/all-period holds, cross-engine active full manifests, scheduled drip work and complete final direct-child indexed evidence govern exact ordered exclusions; an external active original without a proven full manifest blocks. Ordinary unknown holds differ from no-ID dispatching/unknown retry barriers. Canonical safety/local/partition preimages and the unchanged fingerprint function produce comparison data only. Private ledger identity and revision comparisons remain required. Retained whitelisted provider tuples, including wrappers and simultaneous fence copies, fit 8 MiB; the explicit UTF-8 JSON tuple of local snapshot, provider facts and proposal/identity fits 24 MiB, counting repeated serialized occurrences. These are logical limits, not RSS. The controlled owner must checkpoint before/after pure assessment, hashing, serialization and final readers and await close in finally. P1C production proof/guard assembly and P2 strict public variants, dual-output bound and eighth registration remain absent; seven tools and five unfinished tools remain.

Keep stdout exclusively MCP protocol except explicit help/version and local fingerprint/init/migration output. Fixed application errors must not reflect raw exceptions. No default paths/caps, environment-file loader, state initialization at startup, reload loop, reconciliation or scheduler. Restart all cooperating hosts after policy changes.
