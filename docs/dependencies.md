# Dependency decisions

The foundation uses Bun for its runtime, package manager, bundler, and tests. `bun.lock` records the reproducible resolution. Runtime channels in `.mise.toml` follow stable Bun and Node LTS; pnpm is present as a baseline tool but is not used to manage this package. Do not add a second lockfile.

| Dependency                     | Foundation version | Purpose                               |
| ------------------------------ | ------------------ | ------------------------------------- |
| `@modelcontextprotocol/server` | 2.3.1              | MCP registration and stdio            |
| `zod`                          | 4.6.7              | Provider and public output validation |
| `@modelcontextprotocol/client` | 2.3.1              | Development-only protocol tests       |
| `@types/bun`                   | 1.4.3              | Runtime/test types                    |
| TypeScript                     | 6.0.3              | Static checking                       |
| ESLint / `@eslint/js`          | 10.13.0 / 10.0.1   | Linting                               |
| `typescript-eslint`            | 8.72.0             | TypeScript lint rules                 |
| Prettier                       | 3.9.10             | Formatting                            |

Exact versions record the verified foundation resolution, rather than a permanent upgrade policy. Review them together when updating dependencies. The TypeScript 6.0.3 selection is a compatibility exception: typescript-eslint 8.72.0 declares TypeScript `>=4.8.4 <6.1.0`, excluding TypeScript 7. Review this exception when the supported peer range changes. The MCP packages require Node `>=20` for their Node interfaces; the CLI itself runs under Bun. Development was exercised with Bun 1.4.2 and Node 24.21.0; CI selects stable Bun 1.4.3.

Sources: [versioned MCP SDK](https://github.com/modelcontextprotocol/typescript-sdk/tree/v2.3.1), [Bun bundler](https://bun.com/docs/bundler), [typescript-eslint configuration](https://typescript-eslint.io/getting-started/), and [typescript-eslint registry manifest](https://registry.npmjs.org/typescript-eslint/8.72.0). SDK declarations in the installed packages control exact integration details, including `context.mcpReq.signal` for cancellation. Context7 SDK documentation covered 2.3.1; Bun documentation coverage stopped at 1.4.2 and typescript-eslint documentation was unversioned, so exact compatibility was checked against registry metadata and installed types.

The task-status POST uses Bun Fetch request methods, JSON bodies, headers, and `AbortSignal`. Version-tagged Bun 1.4.2 [Fetch documentation](https://github.com/oven-sh/bun/blob/bun-v1.4.2/docs/guides/http/fetch.mdx) covers those options. CI uses Bun 1.4.3, outside that exact documentation target; installed runtime behavior and synthetic transport tests verify this integration. The versioned SDK [tool documentation](https://github.com/modelcontextprotocol/typescript-sdk/blob/v2.3.1/docs/servers/tools.md) covers tool registration and structured output, and its [cancellation documentation](https://github.com/modelcontextprotocol/typescript-sdk/blob/v2.3.1/docs/servers/logging-progress-cancellation.md) covers forwarding `context.mcpReq.signal`.

## Built-in SQLite API

The guarded submission host and explicit local maintenance commands use the V1/V2 ledger through Bun's built-in `bun:sqlite`; this adds no package and changes no dependency resolution. The implementation targets the repository's Bun 1.4.2 development runtime and `bun-types` 1.4.3 declarations. It uses the numeric `SQLITE_OPEN_READWRITE | SQLITE_OPEN_NOFOLLOW` constructor after exclusive POSIX file creation, omits `SQLITE_OPEN_CREATE` during normal open, and casts period timestamps, reservation amounts, returned intent state versions and creation times, and per-intent URL counts to decimal text for safe integer conversion. Schema `user_version` and dispatch compare-and-set state-version reads are numeric. Each writer connection verifies foreign keys, WAL, `synchronous=FULL`, and a 2,000 ms SQLite busy timeout. Those settings do not establish durability beyond the SQLite VFS, filesystem, storage hardware, and operating system. Linux behavior remains subject to the repository's CI verification.

Sources: [Bun 1.4.2 SQLite guide](https://github.com/oven-sh/bun/blob/bun-v1.4.2/docs/runtime/sqlite.mdx), [SQLite transaction documentation](https://www.sqlite.org/lang_transaction.html), [SQLite `busy_timeout`](https://www.sqlite.org/pragma.html#pragma_busy_timeout), [SQLite synchronous pragma](https://www.sqlite.org/pragma.html#pragma_synchronous), and [SQLite WAL documentation](https://www.sqlite.org/wal.html). Bun's installed SQLite declarations were checked in `bun-types` 1.4.3. The child-process test fixture uses Bun 1.4.2's `Bun.spawn` and explicit stdin/stdout pipes; Node-compatible POSIX filesystem calls use the installed Bun runtime's `node:fs` implementation.

V2 maintenance reuses the same driver and schema contracts without new dependencies. It checkpoints WAL outside a transaction, then holds an immediate writer transaction through a bounded guarded `node:fs` descriptor copy, partial-read/write handling, logical backup verification and final file/directory fsync before additive DDL. It does not use a guessed `bun:sqlite.backup()` API, in-memory serialize, VACUUM INTO, directory swap or a new driver. Relevant Context7 Bun 1.4.2 coverage was checked against installed 1.4.3 declarations and owned Bun 1.4.2/SQLite 3.54.0 runtime probes; some main/Bun.SQL/node:sqlite examples did not describe this API and were excluded. Exact event/sequence integers are projected as decimal text instead of rounded JavaScript numbers.

The snapshot uses a guarded READWRITE/NOFOLLOW existing connection with `query_only=ON`, FK/busy settings and inspection of existing WAL mode, then one synchronous deferred read transaction. Closing can checkpoint bookkeeping; successful results require successful handle closure. Sources: [pinned Bun SQLite guide](https://github.com/oven-sh/bun/blob/bun-v1.4.2/docs/runtime/sqlite.mdx), [pinned Bun filesystem compatibility source](https://github.com/oven-sh/bun/tree/bun-v1.4.2/src/js/node), [Node filesystem reference](https://nodejs.org/api/fs.html), [SQLite backup discussion](https://www.sqlite.org/backup.html), [VACUUM](https://www.sqlite.org/lang_vacuum.html), and the transaction/WAL references above. SQLite and Node references are unversioned; local probes establish the selected behavior on this Mac, not every platform. CI Bun 1.4.3/Linux verification is a separate delivery gate. These calls supply no hardware/power-loss guarantee. See [maintenance](state-maintenance.md).
