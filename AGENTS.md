# SpeedyIndex MCP — agent contract

## Purpose

Build an unofficial MCP integration for SpeedyIndex. The Bun/TypeScript stdio server exposes four single-request read tools, three guarded create tools, and read-only `plan_retry`. Four further public tools and one-shot retry execution remain roadmap work.

## Ownership

This root owns project scope, public status, licensing, and the DOX hierarchy. `docs/` owns architecture, dependency notes, roadmap, and provenance; `.github/` owns CI, review automation, and contribution templates. `src/` owns runtime code and `tests/` owns deterministic Bun verification. Root also owns package/build/tooling and community documentation.

## Local Contracts

- This root and its child contracts provide the repository guidance for contributors; access to maintainer-only references is not required. Maintainer agents also follow `~/.agents/instructions/WORKFLOW.md` when installed or provided. The [private baseline workflow](https://github.com/antongulin/baseline/blob/main/baseline/02-agents.md) is a restricted maintainer reference requiring access. Current explicit task instructions and higher-priority platform rules control.
- Read this root and every applicable child `AGENTS.md` before editing. The nearest contract controls local details without weakening the shared DOX discipline.
- Keep roadmap features separate from implemented behavior. Eight tools are implemented: `get_balance`, `list_tasks`, `get_task_status`, `get_task_report`, `create_indexing_task`, `create_index_check`, `create_backlink_check`, and `plan_retry`. `submit_retry`, `compare_reports`, `summarize_campaigns`, `get_retry_history`, and one-shot execution require later scoped work. Public retry dispatch and scheduling remain unimplemented; branch implementation is not release or delivery evidence.
- Submission writes are disabled by default. Preview opens no state and requires no key. Operators explicitly select a private policy, finite independent three-unit caps, expected key binding and canonical state reference; the repository supplies no active values or default paths. Only explicit local new-only init commands create V1 or V2 state. Offline migration requires explicit private paths, a new private backup and draining/stopping all cooperating hosts. Normal submit opens existing state without repair or reset. Policy changes require restarting all cooperating hosts.
- Index checks require explicit private opt-in and selected per-engine three-unit reservation profiles. Missing profiles are unpriced and block submission. Operator reservations are not provider fees. All three create tools share one host coordinator, busy guard and V1 caps/holds; absent policy extensions preserve legacy identity.
- Backlink checks require `enabled: true`, additional explicit private `allowBacklinkChecks: true` and a complete `backlinkCheckReservations` vector. Tokens have a dated local floor of 2 per donor; other-unit fees and target-count pricing effects remain unknown. Explicit zero in another unit is an operator reservation choice, not a zero-fee claim. No active/default values ship. Invalid optional flag/profile fields invalidate the whole policy and block all three create tools until corrected and all cooperating hosts restart. Both new keys absent preserve legacy identity; present false/profile values bind the whole policy digest.
- An optional strict private `retry` object contains exactly `enabled`, `allowUnattributedParents`, and positive safe-integer `maxAttemptsPerSource`. Include it in policy identity only when present; absence preserves the exact legacy digest, and present false/other values bind identity. Malformed retry data invalidates the whole policy and blocks all three create tools. This field alone is only a private prerequisite: it supplies no source verification or public `plan_retry`/`submit_retry` capability.
- Preserve backlink target text (1 to 50 nonblank safe Unicode strings, at most 8,192 UTF-8 bytes each), including case, order and exact duplicates; no DNS normalization. Enforce 10,000 unique donor URLs and a 2 MiB full-body bound. The digest binds targets, while V1 stores ordered donor URLs as unresolved holds across target lists and families, without raw targets, pair rows or schema growth. Durable accepted means acknowledged job creation, not task completion.
- Preserve the V1 ledger and read client boundaries. Local request IDs and acknowledgement hashes provide no provider idempotency, account identity or human authentication. Prepared/dispatching/unknown holds need manual inspection; no automatic release or resend. Explicit offline V1→V2 migration preserves core records/ownership/holds and adds unattributed legacy contexts. Internal V2 snapshots and atomic retry admission supply the planner's local foundation without automatic retry. Snapshots cover only the selected key’s local history across budget scopes/families; legacy ancestry and provider-wide coverage remain unknown. The original local-only retry entry requires current revision and an exact unambiguous local same-engine indexer parent/manifest/subset. Unacknowledged dispatching/unknown retry children block new retry admission; exact replay grants no replacement capability. These checks supply no source eligibility, adoption or paid authority. Never restore stale V1 over new V2 activity; follow the maintenance guide.
- The internal production retry composition captures the same immutable configuration/key/transport as the host’s three create strategies. Internal `planRetry` owns the actual shared busy guard before initial SQL and uses the existing same-key two-pass collector, final coherent readers and per-composition private proof admission. Construction opens no state or network; absent/disabled retry blocks planning while ordinary creates and reads remain available. Exact durable create replay precedes busy/current ACK and new-work availability checks, without a replacement capability.
- One original monotonic budget begins before initial SQL and carries the initial UTC day through observation, CPU/identity/serialization, final readers, proof sealing and awaited native settlement/close. The closed budget stays closed; a final freshness fence uses the original captured record. Conflicts refuse without recomputation. Complete no_source gets a final same-ledger/revision/time/day fence without invented parent or quote. Cleanup failure invalidates pending proof and permanently blocks this host/composition’s new plans/creates until restart, while pure preview and read-only exact durable replay remain available. Clean settled failure permits reuse. SQL/CPU checkpoints are best-effort and queued JS cancellation requires an actual I/O opportunity; no await spans a transaction. Safe frozen host results omit private candidates, proofs, raw credential bindings, paths, ledger identity, inspection IDs and raw observations. Opaque policy/revision/authorization/body/quote commitments remain public comparison data and cannot reconstruct discarded history. The parent-first controlled verifier remains a separate constructor form; mixed production/fixture authority is rejected.
- `plan_retry` accepts only optional `searchEngine: "google" | "yandex"`, defaulting to Google. Its existing configured host requires enabled private policy/retry and complete existing V2 state. Planning creates no jobs, reservations, retry rows or adopted parents. Latest-source and two-pass observations remain non-atomic provider evidence; local manifests and permitted external observed corpora retain their distinct provenance and unknown ancestry. Preserve `ready`, `no_source`, `blocked`, and fixed `error` variants, with application `isError` true exactly for `error`. SDK input rejection is separate. Ready identities grant comparison data, no admission or paid authority.
- Bound the complete `plan_retry` application envelope inclusively to 2,097,152 UTF-8 bytes, counting `isError`, escaped JSON text and its duplicate `structuredContent`. Validate, freeze and serialize within the original owner budget before final freshness and awaited close; the adapter returns that owned envelope without rebuilding it. This bound excludes SDK JSON-RPC framing and does not measure RSS or guarantee hard latency. Logical read-only snapshots may change physical WAL/SHM bookkeeping. SDK cancellation can suppress the application reply; native settlement and owner completion must precede reuse.
- Keep public documentation free of credentials, account data, private task records, and machine-specific paths. Provider calls and paid submissions require task-specific authority.
